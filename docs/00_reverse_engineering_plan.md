# 逆向 Sac《小王子》→ 制作《三体》AI 动画：拆解与执行方案

> 原型作品：Sac（X @Saccc_c）用 AI 在 16 天内做出的《小王子》全景 3D 剧情探索游戏（littleprince.dev），发布数日播放量超 300 万；他同时用 Opus 5.5 在 Blender 里凭一句提示词渲染了一段 33 秒预告片。

## 一、逆向：Sac 的管线到底是什么

### 1. 五步流水线（原作公开版）

| 岗位 | 工具 | 做什么 |
|---|---|---|
| 策划 | Fable 5.1 | 写 PRD：把原著拆成场景清单、角色人设、关键剧情线 |
| 原画 | GPT Image 2.5 | 先出一张"最满意"的场景效果图定光影/色调/构图，再补俯视图、斜侧视图、局部细节；角色出 T-Pose 四视图 |
| 建模与动画 | Tripo + Auto-Rig Pro + Mixamo | 道具用 Tripo H3.1（高精、保硬表面细节）；角色用 Smart Mesh P2.0（可控面数、四边面拓扑）；Auto-Rig Pro 绑骨蒙皮；Mixamo 下载 FBX 动作切片 |
| 主程 | Claude Opus 5.5 | 通过 Blender CLI/MCP、Unity MCP 直接下场：导入资产、搭地形、按参考图摆道具、校光比与视锥、动作重定向、IK 微调 |
| 维护 | Astra | 进度跟踪、迭代、修 bug |

### 2. 真正决定成败的两个工程动作

**（a）视觉锚点先行。** 绝不让代码模型凭文字空想。先用图像模型抽出一张完全满意的 2D 参考图，再让 3D 生成和场景复刻"死咬"这张图交差。原文提示词：

> 基于上传的场景参考图，帮我生成一张该场景的全面貌参考图片，包括整体环境的多视角视图以及局部细节的展示。

**（b）执行与质检分离（盲审 Agent）。** 搭场景的 AI 和挑错的 AI 不是同一个。独立审查 Agent 从正面、侧面、玩家主视角截图，对着参考图盲审，发现穿模、比例差、光照不符就打回重做，直到与原画基本一致。

### 3. 精细动作的处理套路

通用动作库对不上"带道具接触"的动作（提水壶、弯腰浇水）。做法：选趋势最接近的 Mixamo 动作打底 → 让 Opus 5.5 用 Auto-Rig Pro 手臂 IK 控制器改姿势。原文提示词：

> 请参考提供的 Mixamo 动作，保留其中适用的部分，并使用 Auto-Rig Pro 的手臂 IK 控制器调整手臂姿势，配合手指握持和水壶位置的细节修正，补全提水壶动作。确保手掌与把手接触稳定、提起过程自然，避免穿模、握持脱离或水壶悬空。

### 4. 为什么是它火了（不可忽略的"非技术"部分）

- **题材选择克制**：没选赛博朋克/meme，选了一本关于孤独与驯养的童话，整体调性必须温柔、留白，不能堆特效。
- **低多边形是主动选择**，手作质感与原著水彩气质吻合；构图故意让角色在大场景里很小，制造孤独感。
- **每个星球都在"读"原著**：国王星球用夸张比例差做荒诞，虚荣者星球做成剧场，地理学家书房堆满藏书与浑天仪。
- **在一个项目上泡了两周以上**，反复为一个握持动作迭代手指与把手的接触。

> 结论：工具链决定"能不能"，审美与耐心决定"好不好"。逆向时两者都要抄。

## 二、从"游戏"到"动画"：管线怎么改

Sac 的终点是 Unity 可玩游戏；做《三体》动画，终点换成 Blender 渲染视频。只需改最后一环，其余完全复用，而且更简单（不用写交互逻辑和打包）。

```
Sac：PRD → 参考图 → Tripo 资产 → Opus 在 Blender 搭场景/绑骨/动作 → Unity 打包成游戏
我们：PRD(分镜本) → 参考图 → Tripo 资产 → Agent 在 Blender 搭场景/绑骨/动作 → Blender 相机动画 + 渲染 → 剪辑配音
```

多出来的两件事：
1. **分镜脚本**代替游戏关卡设计（每个镜头：时长、机位、运镜、画面内容、声音）。
2. **相机动画与渲染**：让 Agent 在 Blender 里写相机关键帧（Sac 的 33 秒预告片正是这样做的），用 Eevee 渲染低多边形风格足够快。

## 三、《三体》的改编选择

### 1. 为什么《三体》适合这条管线

- 《小王子》的结构是"一颗星球一章"，《三体》第一部里的**"三体游戏"**天然也是"一个纪元一关"，且游戏本身在原著里就是低多边形/VR 质感——风格合法性直接来自原著。
- 原著中最震撼的画面是**人在巨大尺度面前的渺小**（人列计算机、三日凌空、古筝行动、二向箔），正好对应 Sac "角色在大场景中很小"的构图哲学。
- 低多边形 + 远景为主，可以绕开 AI 3D 最大的短板：写实人脸和大段对白口型。

### 2. 建议的章节结构（对应"星球"）

| 章 | 场景 | 核心画面 | 关键资产 | 难度 |
|---|---|---|---|---|
| 序章 | 红岸基地 | 雷达峰上的巨型天线，叶文洁按下发射键 | 抛物面天线、山顶基站、控制台 | 低 |
| 一 | 三体游戏·乱纪元 | 脱水的人被卷成皮卷，烈日下的荒原 | 荒原地形、脱水人卷、金字塔 | 低 |
| 二 | 三体游戏·人列计算机 | 三千万士兵排成的计算机主板，牛顿、冯·诺依曼俯视 | 士兵（实例化）、旗语、巨型方阵地面 | 中 |
| 三 | 三体游戏·三日凌空 | 三颗太阳同时升起，一切被蒸发 | 三个发光球、热浪材质、崩塌建筑 | 中 |
| 四 | 古筝行动 | 巴拿马运河，"审判日"号被纳米丝切成薄片 | 巨轮、运河两岸、琴弦（极细几何体） | 高 |
| 尾声 | 智子 | 质子展开成二维平面，包裹整个三体星 | 球体、二维展开面、星球 | 中 |

> **建议先做第一、二章**（三体游戏），一周内能看到成片；红岸作为序章可用静帧+运镜解决。

### 3. 视觉基调（对应 Sac 的"温柔克制"）

《三体》的关键词是**冷峻、宏大、沉默**。具体规则：

- 低多边形，但**色彩收敛**：乱纪元用灰土 + 刺眼白昼；恒纪元用冷蓝；红岸用 70 年代军绿与铁锈红。
- 构图永远**人小、物大**：人物占画面高度不超过 1/10。
- 运镜只用**缓推、缓摇、缓升**三种，节奏向 Sac 的开场镜头（小王子坐椅看云海）看齐。
- 声音以低频环境声 + 稀疏钢琴为主，不用交响式配乐。

## 四、逐步执行手册（含国内可用替代）

### 工具选择

| 环节 | Sac 原用 | 国内可直接用 / 替代 | 备注 |
|---|---|---|---|
| PRD / 分镜本 | Fable 5.1 | 任一强对话模型（Kimi、DeepSeek、通义千问） | 文本任务，替代成本最低 |
| 参考图 | GPT Image 2.5 | 即梦（Seedream）、可灵图片、通义万相 | 要求支持"参考图 + 多视角"生成 |
| 3D 资产 | Tripo（VAST，国内公司） | Tripo 直接用；备选腾讯混元 3D | Tripo 的四边面拓扑是绑骨不崩的关键 |
| 绑骨 | Auto-Rig Pro（付费插件） | Auto-Rig Pro；备选 Blender 自带 Rigify、Tripo 内置绑骨（需测试） | 人物数量少时成本可控 |
| 动作库 | Mixamo（需外网） | Mixamo；备选 Tripo 内置动作、Blender 手 K | 本片动作极少，远景为主，影响小 |
| 代码 Agent | Claude Opus 5.5 + Blender MCP | Claude 可用最佳；否则 Kimi K2 / Qwen3-Coder / DeepSeek 接 Blender MCP | 核心要求：能读场景、写脚本、执行、截图自查 |
| 渲染 | Unity（游戏） | **Blender Eevee** | 低多边形风格 Eevee 速度快，1080p 单帧秒级 |
| 剪辑配音 | — | 剪映 / DaVinci Resolve；配音用即梦或豆包 TTS | 旁白用原著原句 |

### Step 0：PRD / 分镜本（半天）

提示词模板：

> 你是三维动画导演。基于《三体》第一部"三体游戏"中"乱纪元·脱水"与"人列计算机"两段，写一份 3 分钟低多边形动画的制作文档，包括：①场景清单（每个场景的地形、主要物件、光照时段）；②角色清单（外观关键词、是否需要绑骨、动作列表）；③分镜表（镜头号、时长、机位、运镜、画面内容、旁白原文、环境音）；④每个场景需要单独建模的资产 vs 可用基础几何体搭建的物件。构图原则：人物在画面中极小，运镜只用缓推、缓摇、缓升。

### Step 1：视觉锚点（1 天）

1. 每个场景先生成 5–10 张，**只选一张**最满意的作为"主锚点"。
2. 用 Sac 的多视角提示词补俯视图、斜侧视图、局部细节。
3. 角色出 T-Pose 四视图。

示例提示词（乱纪元）：

> 低多边形 3D 渲染风格，三体游戏中的乱纪元荒原。无垠龟裂的灰褐色大地，远处一座简洁几何感的金字塔，天空中一颗刺眼的巨大白色太阳，地平线轻微弯曲暗示这是另一颗行星。前景极小的一个人影披着破旧斗篷。色彩收敛，强烈的顶光与长投影，氛围冷峻、寂静、宏大。无文字，无水印。

示例提示词（人列计算机）：

> 低多边形 3D 渲染风格，俯瞰视角。三千万士兵排列成的巨大电路板状方阵铺满平原，每个士兵举着黑白旗，方阵内有清晰的"总线"通道。远处一座高台，三个微小的人影俯视全局。晨光，长影，秩序感与荒诞感并存。

### Step 2：资产拆解与生成（2–3 天）

让 Agent 对每张主锚点图执行：

> 把这张场景参考图拆成资产清单，分三类：A 必须用 Tripo 生成的独特造型物件；B 可用 Blender 基础几何体 + 简单修改器搭建的物件；C 可用粒子/实例化批量生成的物件。每一项给出数量、尺寸比例、在俯视图中的位置。

- A 类（天线、金字塔、巨轮、控制台）→ Tripo H3.1 高精。
- 人物（叶文洁、汪淼、脱水人、士兵基准模型）→ Tripo Smart Mesh P2.0，控制面数在 5k 以下，便于实例化三万个士兵。
- B/C 类直接让 Agent 在 Blender 里写脚本生成（这正是 Sac 预告片"用简单几何体做纵深"的做法）。

### Step 3：Agent 在 Blender 搭场景（3–4 天）

每个场景一个任务，交给 Agent 的材料 = 主锚点图 + 多视角图 + 资产文件。提示词：

> 按参考图在 Blender 中复刻该场景：导入 /assets 下的模型，用基础几何体搭建地形与远景，按俯视图摆放物件，设置太阳光方向与色温使光比接近参考图。完成后从正面、斜侧、主相机三个机位各渲染一张 960×540 预览图保存到 /review。

然后**换一个独立对话/独立 Agent** 做盲审：

> 你是审片人。对比 /review 下三张截图与参考图，列出所有差异（比例、位置、缺失物件、光照、穿模），按严重程度排序，给出具体修改指令。不要自己动手修。

执行 Agent 根据修改指令改，循环直到审片人判定"基本一致"。通常 3–5 轮。

### Step 4：角色、绑骨与动作（2 天）

- 远景角色（士兵、脱水人）：不绑骨，用静态姿势实例化即可。
- 近景角色（叶文洁按键、汪淼环顾）：Auto-Rig Pro 绑骨 → Mixamo 动作打底 → 用 Sac 的 IK 提示词改"手接触控制台按钮"。
- 士兵旗语：给基准模型做两个 Pose（黑旗/白旗），用几何节点随机切换即可形成"计算中"的波浪感。

### Step 5：相机动画与渲染（2 天）

> 为该场景写相机动画：总时长 X 秒，24fps。镜头 1 从地面低角度缓升至俯瞰（0–8s），镜头 2 固定远景缓推（8–15s）。所有运动使用缓入缓出。Eevee 渲染，1920×1080，输出 PNG 序列到 /render/scene01。

先低分辨率跑一遍 animatic（480p），确认节奏后再正式渲染。

### Step 6：剪辑、旁白、声音（1–2 天）

- 旁白用原著原句（如"脱水——"、"这是一台计算机！"），TTS 或自己录。
- 环境声只用低频风声、金属共振、极少量钢琴。
- 片头片尾注明"非官方同人改编，用于教学/研究，原著 © 刘慈欣"。
