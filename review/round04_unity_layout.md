# 盲审记录 · 第 4 轮（Unity 布局虚拟 Game 视图）

工具：blender/render_layout.py —— 读取 Unity 工程里的 GLB 与 layout JSON，用 scripts/coords.py 把 Unity 坐标反算回 Blender，从玩家出生点身后 6 m 渲染。等价于 Unity 首次运行时 Game 视图应看到的画面。

## 本轮修掉的两个系统性错误（在 Unity 里会直接暴露）
1. **坐标换算错误**：旧 `to_unity` 用 (x, z, y) 映射，但 glTFast 按规范将 glTF 右手系转为 Unity 左手系时反转 X 轴，正确映射是 (−x, z, −y)；旋转亦需按矩阵共轭换算（`coords.blender_euler_to_unity`）。影响：所有 layout 摆放的物体相对于烘焙了世界坐标的 GLB（地面、悬崖、云海、窗灯）整体旋转 180°，红岸天线会掉到悬崖外。
2. **物体变换读取过期 + GLB 带世界变换**：`matrix_world` 在设置 location 后未刷新，导致 4 栋营房全部堆在原点、围栏偏移 54 m；同时 GLB 导出时带了物体变换，与 layout 叠加成双重变换。现在所有生成器末尾 `bake()` 烘焙变换，`export_glb` 单物体导出前归零，`to_unity` 先 `view_layer.update()`。

另：方阵 origin、太阳方向（yaw = 180 − rz）、三日位置（z = −900）、玩家出生朝向（面向场景主体 +Y）一并修正。

| 人列计算机 | 玩家面向方阵，高台在左前方，群山在尽头，8288/36512 抽样士兵排布正确 | 高台仍是灰色方块（B 类），可换 Tripo 石砌高台；士兵朝向应面向高台（已改 yaw=0，待 Unity 确认） |

## 结论
坐标链路（Blender → glTF → glTFast → Unity）已用数值自检（scripts/coords.py）+ 视觉复现双重验证；Unity 首跑的风险从"场景整体错位"降为"小物件贴地与距离微调"。
